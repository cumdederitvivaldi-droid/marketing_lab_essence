must-use 이유 ｜ 3가지 구조적 해자 개요

경쟁 MVNO가 절대 복제할 수 없는 3가지 구조

① 오토파일럿

매달 사용량을 자동 분석해 더 적합한 요금제로 자동 전환 — 유저는 요금제를 다시는 신경 쓸 필요가 없다.

② 데이터 자산화

남는 데이터가 소멸되지 않고 모요포인트로 자동 적립 — 내 데이터가 사라지지 않는 유일한 곳.

③ 요금다운보장

가입 후 더 싼 요금제가 나오면 자동 전환되거나 차액을 보상받는다 — 모요에서 가입하면 손해를 안 본다.

셋 다 모요의 데이터·비교엔진·정산 인프라가 있어야만 가능한 구조 — 사은품·0원 마케팅으로는 복제 불가능한 해자다.

must-use 이유 ① ｜ 오토파일럿

가입하고 잊으면, 알아서 최적화되는 요금제

매달 사용량 자동 분석→더 적합한 요금제 매칭→자동 전환

유저 개입 없이 매달 반복 — 구독형으로 계속 최적 요금제를 유지시켜준다

왜 필요한가

유저는 매달 요금제를 직접 비교하지 않는다 — 방치가 기본값이라 손해가 누적된다.

왜 모요만 가능한가

전체 요금제 비교엔진 + 사용량 데이터 + 가입·전환 인프라를 동시에 가진 곳은 모요뿐이다.

📌 가입하고 잊으면 끝 — 요금제를 다시는 신경 쓸 필요가 없다.

must-use 이유 ② ｜ 데이터 자산화

남는 데이터가 사라지지 않는 유일한 곳

매달 미사용 데이터 잔량→모요포인트 자동 적립→포인트몰·현금화로 소진

이미 운영 중인 포인트몰·현금화 인프라를 그대로 재사용해 적립분을 실제로 쓸 수 있게 한다

왜 필요한가

원래 데이터는 이월 없이 매달 그냥 소멸되는 자원이다 — 유저 입장에서 순수 손실.

왜 모요만 가능한가

적립만으론 의미 없다 — 포인트몰·현금화 인프라가 이미 있어야 실제로 소진·환급이 가능하다.

📌 내 데이터가 사라지지 않는 유일한 곳 — 다른 통신사·MVNO엔 이 인프라가 없다.

must-use 이유 ③ ｜ 요금다운보장

가입 후에도 손해를 안 본다는 계약적 신뢰

더 싼 요금제 출시 감지→자동 전환 또는 차액 보상→유저는 항상 최저가 유지

전체 요금제 실시간 비교 + 정산 인프라가 있어야만 이 보장을 자동으로 실행할 수 있다

왜 필요한가

기존 통신 시장은 가입 시점 가격에 계속 묶여 손해가 누적되는 구조였다.

왜 모요만 가능한가

실시간 요금제 비교 데이터와 정산 인프라를 함께 가진 곳만 자동 전환·보상을 실행할 수 있다.

📌 모요에서 가입하면 손해를 안 본다 — 가격이 아니라 계약적 신뢰다.

"못 지키면 손실"이 아니라 — "안 지키면 회수"로 바꾼다

✗ 과거 우려

최소유지기간을 못 지키면 모요가 손실을 떠안는다

선지급한 포인트를 유저가 조기 해지해버리면 회수 수단이 없어 리스크가 전부 모요에 남는 구조였다.

✓ 이번 답

약관에 clawback(회수) 조건 명시

최소 유지기간(약정) 미충족 중도해지 시 지급된 포인트를 회수한다는 조건을 약관에 명시 — 리스크를 유저에게 전가하지 않고, 모요가 조건부로 통제한다.

핵심은 "손실을 없앤다"가 아니라 "손실 조건을 계약으로 통제한다"는 것 — 다음 ROI 파트에서 이 리스크를 정량화한다.
