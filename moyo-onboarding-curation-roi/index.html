문제 리캡 ｜ 서비스가 늘수록 커지는 온보딩 이탈

서비스가 풍부해질수록, 신규·시니어 유저는 길을 잃는다

🧭 현재 서비스 구성 — 요금제 비교 · 휴대폰(자급제) · 인터넷 결합 · 랭킹 · 커뮤니티까지 폭넓게 운영 중 → 무엇을 먼저 봐야 할지 안내가 없음

왜 문제인가

  • 신규 앱설치 유저는 "무엇을 찾아야 할지" 판단할 사전 지식이 없음
  • 시니어 유저는 다수 메뉴·비교 화면 자체가 진입장벽
  • 결과적으로 핵심서비스(요금제 비교 등) 도달 전에 이탈

10명 중 4명이 요금제 비교조차 보지 못하고 이탈 — 이미 광고비를 쓰고 데려온 유저인데도.

① 단계별 큐레이션 온보딩

"무엇을 찾으세요?" 3~4개 질문으로 안내

  • 신규 진입 시 짧은 질문으로 요금제·폰·결합까지 서비스 전체를 안내
  • 통신을 잘 몰라도, 시니어여도 길을 잃지 않는 첫 화면
  • 질문에 따라 첫 핵심서비스로 바로 연결 → 이탈 지점 자체를 줄임
② 개인화 홈 대시보드

진단·알림·추천을 한 화면에

  • 내 통신 현황·진단·할 일·추천을 홈 한 화면에 통합
  • 재방문 시에도 "다음에 뭐 하지?"를 모요가 먼저 제안
  • 여러 서비스가 흩어져 있던 경험을 하나의 축으로 재구성
🏦 벤치마킹 — 토스 홈: 수십 개 금융 서비스 중 "내게 필요한 것만" 큐레이션해 보여주는 구조. 모요도 같은 원리를 온보딩·홈에 적용.

ROI 검증 ④ ｜ 이 매출의 성격

이 매출은 "추가 광고비 없이" 발생하는 순증분이다

1유저는 이미 광고비(CAC)를 지불하고 앱을 설치한 상태
2기존에는 온보딩 복잡도 때문에 핵심서비스 도달 전 이탈
3큐레이션 온보딩으로 이미 유입된 유저를 회생시키는 구조
4새 유저를 사는 것이 아니므로 CAC 재투입이 필요 없음
시나리오 B 기준
1.8억원 매출
= 추가 광고비 0원
신규 획득(CAC 지불) 없이, 이미 유입된 유저의 온보딩 이탈만 줄여서 만드는 매출 — 광고비 낭비 감소와 매출 증가가 동시에 일어나는 구조.

즉 이 ROI는 기존 마케팅 예산과 경쟁하지 않는 순증분 — 예산 재배분 없이도 실행 가능하다.

실행 ① ｜ 단계별 로드맵

프로토타입 → 실측 → 롤아웃, 3단계로 검증한다

0–1개월 · 설계

프로토타입 설계

  • 온보딩 질문 플로우 설계(3~4문항)
  • 개인화 홈 대시보드 프로토타입 제작
→
1–3개월 · 실측

A/B 테스트

  • 기존 온보딩 vs 큐레이션 온보딩 A/B 테스트
  • 실제 이탈률 개선폭을 측정해 A/B/C 시나리오 검증
→
3개월~ · 확장

전체 롤아웃

  • 실측 개선폭 기준으로 전체 유저 대상 롤아웃
  • 개인화 홈을 서비스 전체 진입점으로 확장

핵심은 가정치(40%→A/B/C)를 실측으로 검증한 뒤 확장하는 것 — 소규모 A/B 테스트가 선행 관문.
